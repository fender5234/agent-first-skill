# Agent-First Development Workflow

## 1. Знакомство с задачей
- Читаешь ТЗ, понимаешь бизнес-требования
- Помещаешь ТЗ в проект (`documentation/requirements.md`) — чтобы агент тоже имел контекст

## 2. Interview → План
- С помощью скилла `/interview` агент читает ТЗ, задаёт уточняющие вопросы
- Определяете архитектуру:
  - **Фронтенд:** модульная архитектура (`src/modules/`). Один модуль = один бизнес-домен = один блок в YAML
  - **Бэкенд:** модульная архитектура + REST API (`app/modules/`). Один модуль = один ресурс = один блок в YAML
  - **Не FSD** — в agent-first модульная выгоднее: 1:1 mapping модуль→блок, меньше токенов на ориентирование, проще зависимости
- Создаёте план выполнения с критериями приёмки и контрольными точками (milestones)
- План сохраняется в `.md` — агент читает его, выполняет пошагово, отмечает выполнение

## 3. Ревью плана
- Проверяешь покрытие ТЗ — все ли требования отражены в плане
- Корректируешь приоритеты и последовательность задач
- Проверяешь зависимости между задачами

## 4. AF Setup
- Настраиваешь структуру проекта под AF на основе утверждённого плана и архитектуры
- `/agent-first-setup` — создаёт YAML-манифесты, validate.py, pre-commit, CLAUDE.md
- Создаёшь ADR-001 (выбор стека/архитектуры) — фиксируешь обоснование решений

## 5. Выполнение по плану через AF
- Каждый модуль/фича выполняется через 8-шаговый AF Feature Workflow:
  1. Агент читает манифесты → выводит gotchas
  2. Проверяет документацию через context7
  3. Структурирует решение через sequential-thinking
  4. **Пишет тесты ключевых сценариев модуля** (Test-First — до реализации)
  5. Пишет реализацию с KISS/DRY/SOLID
  6. Прогоняет тесты — зелёные → продолжает, красные → фиксит
  7. Обновляет YAML-манифесты
  8. Коммит (pre-commit валидирует)
- На контрольных точках (milestones) — проверка работоспособности и соответствия ТЗ

## 6. Финальная проверка
- Дрейф-аудит (`проведи дрейф-аудит`) — YAML соответствует коду
- Прогон валидатора (`python documentation/validate.py`)
- Проверка соответствия результата ТЗ
